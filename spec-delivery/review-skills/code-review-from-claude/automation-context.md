# Spec Delivery bound invocation

This file applies only when this package is explicitly bound as `prReview` by Spec Delivery. The standalone method in `SKILL.md` is otherwise unchanged. The workflow supplies a fixed PR, full head and base commits, issue/spec links, and either a `regular` or independent `fresh` round.

1. Read the archived `SKILL.md`, this file, and `automation-contract.json` from the source bundle. Check that the PR is open, reviewable, and still at the supplied head/base. If it is closed or draft, return `skipped` with the reason. A simple PR or one previously reviewed still needs this mandatory full-round review; do not call it complete because of either shortcut. If review cannot finish, return `incomplete`.
2. Register the contract's named child tasks through `skill-delegate` under this invocation. Use distinct L2 reviewers for the five independent perspectives in `SKILL.md`; the lightweight preparation tasks may use a faster configured tier. Wait for each required child to complete through `skill-children`. Do not start hidden child agents outside the workflow ledger. For each candidate issue, register a separate independent confirmation child and pass the **whole scoring rubric** from step 5 of `SKILL.md` verbatim. Keep the issue-to-confirmation mapping in the report and evidence. The five perspectives, confirmations, scale, and ≥50 rule come from this package, not the Spec Delivery core.
3. A finding retained by the method blocks the current candidate: finish the skill as `changes_required`, `blocking:true`. If the full review finds none, finish as `pass`, `blocking:false`. Produce a nonempty final Markdown report for **both** outcomes, including the PR and full head/base, reviewed scope, completed perspectives and confirmations, retained findings or an explicit no-issues conclusion, and any limitations. The report is the skill's original `rawOutputPath`; attach source observations as `evidencePaths`. Do not post it yourself: the workflow publishes these exact report bytes with an idempotency marker after verifying the skill receipt.
4. Use the host's actual terminal skill result receipt with the invocation ID, job ID, native session, binding fingerprint, execution mode, and loaded-file hashes. Call `skill-finish` and then return outer status `reviewed` with `data.skillInvocationIds:[id]`. A skipped or incomplete skill must be reported as an incomplete outer result with the matching reason. An actor-generated summary, empty findings list, or existing PR comment does not replace this receipt.
5. In the `fresh` round, start with a new host context and the raw PR diff, issue/spec, repository guidance and tests. Do not read or pass the regular report, previous verdicts, author arguments, or handoff. A changed head/base or skill package fingerprint requires a new valid review round before results can be combined.

The package contract declares only the default method's required preparatory and perspective child keys. A different bound package can declare another topology or no contract; the workflow consumes its complete terminal blocking result without imposing this package's lenses or scale.
