# 执行效率与恢复优化

来源：用户于 2026-09-25 确认按真实 ZCode 测试复盘的建议优化。实现范围由本文件固定，不修改测试 spec、已合并 PR 或原运行证据。

用户输入保持 spec、目标分支、L1/L2/L3 实际模型。L1 决定预算。保留作者双轴自检、L2 五视角 regular 与 fresh、独立问题确认、置信度 ≥50 的处理门槛、验收/CI/人工边界及合并后清理要求。

## 行为

- 多工单并行计划与实现。每次运行的目标分支只允许一个候选进入完整最终验证区间，队外候选到队首才集成最新基线。依赖释放优先，同时用有限插队次数保护等待者。真实外部变化继续使证据失效；重复失效计入有限重规划预算。
- 普通观测批量读取易变状态，验收和合并即时读取 CI。瞬时只读错误有界重试，权限错误/不完整结果明确失败。完成回执可共享同次观测，不能把缓存结果冒充当前门禁。
- 宿主负责绑定真实模型/任务身份、持久化 actor 返回值及逐项收取；不以文件存在代替任务完成。缺证据拒绝。重复登记幂等，坏结果不污染其它完成任务。保留传统 CLI 协议供已有宿主调用。
- 主控驱动所有 executor；认领固定基线并保留稳定远端标记，关闭与清理由命令执行。命令结果先持久化再提交；原进程确认退出后可恢复，已完成测试不重跑。
- 重复 finding 使用稳定的路径/规则/触发身份合并，原始来源均保留。同一候选的 regular/fresh 出现门槛两侧分歧，交新 L1 明确裁决。fresh 的初始材料不带旧结论。
- 交接携带有限的当前索引，旧结果保留按需查阅。临时实验通过测试配额入口执行，保留失败证据。时间、用量缺失记为未知，不能估造。
- 模型路由调整要求先核对并停止在途任务，保留已完成证据。退役运行不能被常规调度或 resume 自动复活。

## 验证边界

通过调度内核、CLI 与真实临时 Git 工作区、GitHub/原生 facade 适配接口进行行为测试。外部 GitHub 使用独立模拟响应；不在验证本包时创建真实工单、评论或 PR。真实测试仓库只用于只读验证批量查询。完整测试后进行独立 Standards/Spec 审查。

原生 ZCode 编译与真实 provider/模型耗时需要在 ZCode 中再次运行；本地 facade 测试只验证生成脚本的控制流，不冒称原生端到端通过。
